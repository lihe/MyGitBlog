如果你理解了 ZeRO，你基本就理解了：



- 为什么 100B 模型能训练
- 为什么优化器状态是显存杀手
- 为什么分布式训练要分 3 个阶段





我从 **问题背景 → ZeRO 的核心思想 → 三个阶段（Stage 1/2/3）→ 数学内存分析 → 与数据并行对比 → 与 FSDP 区别 → 实际效果** 给你讲清楚。



------





# **一、问题背景：普通数据并行的内存浪费**





假设模型参数量为 P。



用 Adam 训练，每张卡需要存：



- 参数：P
- 梯度：P
- 动量 m：P
- 动量 v：P





总共：



4P



如果有 8 张 GPU，数据并行方式是：



> 每张 GPU 都存一份完整模型



所以总显存消耗是：



$8 \times 4P$



⚠️ 但这些参数是完全一样的！



这就是巨大浪费。



------





# **二、ZeRO 的核心思想**





ZeRO = **Zero Redundancy Optimizer**



核心目标：



> 消除数据并行中的冗余



它做的事情：



> 把模型的不同部分分散到不同 GPU 上存储



也就是说：



不是每张卡都存完整模型。



------





# **三、ZeRO 的三阶段（Stage 1/2/3）**





------





# **🔹 Stage 1：优化器状态分片**





分什么？



- 动量 m
- 动量 v





参数和梯度仍然完整复制。



------





### **内存变化**





原来每卡：



参数 + 梯度 + 2×优化器状态



Stage 1：



- 每卡只存 1/N 的优化器状态





内存大幅减少。



------





# **🔹 Stage 2：梯度分片**





在 Stage 1 基础上再分：



- 梯度





现在每卡只存：



- 全量参数
- 1/N 梯度
- 1/N 优化器状态





------





# **🔹 Stage 3：参数也分片**





最强阶段。



- 参数也被分片
- 每卡只存 1/N 参数





训练时：



- forward 前临时 gather 参数
- backward 后再分散





现在每卡存：



$\frac{参数}{N} + \frac{梯度}{N} + \frac{优化器状态}{N}$



显存理论上缩小 N 倍。



------





# **四、数学内存对比**





设：



- P = 参数量
- N = GPU 数





------





### **普通数据并行**





4P



每卡。



------





### **ZeRO Stage 3**





$\frac{4P}{N}$



每卡。



------



如果 N=8：



显存减少 8 倍。



这就是为什么：



> 100B 模型可以在 8 张卡上训练



------





# **五、ZeRO 和数据并行的区别**



| **方法** | **参数** | **梯度** | **优化器状态** |
| -------- | -------- | -------- | -------------- |
| 数据并行 | 全复制   | 全复制   | 全复制         |
| ZeRO-1   | 全复制   | 全复制   | 分片           |
| ZeRO-2   | 全复制   | 分片     | 分片           |
| ZeRO-3   | 分片     | 分片     | 分片           |



------





# **六、为什么 Stage 3 最难？**





因为：



- forward 需要完整参数
- backward 需要完整梯度





所以：



需要大量通信（all-gather）



通信代价很大。



------





# **七、ZeRO 和 FSDP 的关系**





FSDP（Fully Sharded Data Parallel）本质上：



> 是 PyTorch 原生的 ZeRO Stage 3



区别：



- ZeRO 来自 DeepSpeed
- FSDP 是 PyTorch 实现





思想一样。



------





# **八、ZeRO-Offload**





如果 GPU 内存仍然不够：



- 把优化器状态放到 CPU
- 甚至 NVMe





这叫：



> ZeRO-Offload



代价：



- 通信变慢





------





# **九、和 Checkpoint 的关系**





ZeRO 优化：



- 参数
- 梯度
- 优化器状态





Checkpoint 优化：



- Activation





二者互补。



------





# **十、一个直观类比**





普通数据并行：



8 个人，每人背一整套工具箱。



ZeRO Stage 3：



8 个人，每人背 1/8 工具。



需要用时：



互相借。



------





# **十一、为什么 ZeRO 不影响模型结果？**





因为：



- 数值计算完全一样
- 只是存储方式改变
- 通过 all-reduce 保证一致性





------





# **十二、真实世界效果**





例如：



- 7B 模型
- Adam
- fp16





普通训练：每卡 40GB+



ZeRO-3：每卡 6~8GB



差距巨大。



------





# **十三、面试回答模板**





如果问：



> 什么是 ZeRO 分片？



可以回答：



> ZeRO（Zero Redundancy Optimizer）是一种分布式训练优化技术，用于消除数据并行中的冗余存储。它通过分片优化器状态、梯度和参数（Stage 1/2/3）来减少单卡显存占用，理论上可将显存需求降低到原来的 1/N，是大模型训练的核心技术。
