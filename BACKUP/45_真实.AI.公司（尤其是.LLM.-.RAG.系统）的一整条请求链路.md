# [真实 AI 公司（尤其是 LLM / RAG 系统）的一整条请求链路](https://github.com/lihe/MyGitBlog/issues/45)

这个问题其实就是 **真实 AI 公司（尤其是 LLM / RAG 系统）的一整条请求链路**。

从用户输入问题到最终返回答案，通常会经历 **10+ 个步骤**。



我给你按 **真实工业级架构流程**讲一遍（这也是很多 AI 面试非常喜欢问的系统设计题）。



------





# **一、整体流程（先看全局）**





一个真实 AI 系统通常是这样：

```
User
 ↓
CDN / API Gateway
 ↓
Load Balancer
 ↓
API Service (FastAPI / Go)
 ↓
Query Processing
 ↓
Retrieval (Vector DB / BM25)
 ↓
Reranker
 ↓
Prompt Construction
 ↓
LLM Inference
 ↓
Post-processing
 ↓
Return Response
```

可以理解为：



> **用户问题 → 检索知识 → 组织 Prompt → LLM 生成答案 → 返回**



------





# **二、详细流程（一步一步）**





我们假设用户问：

```
RTX4090 显卡功耗是多少？
```



------





# **Step 1 用户请求**





用户在：



- Web
- 手机 App
- Chatbot





输入：

```
RTX4090 显卡功耗是多少？
```

客户端发送请求：

```
POST /chat
```



------





# **Step 2 CDN / API Gateway**





请求先进入：

```
API Gateway
```

例如：



- Kong
- AWS API Gateway
- Nginx
- Apisix





作用：

| **功能** | **解释**        |
| -------- | --------------- |
| 鉴权     | API Key / Token |
| 限流     | 防止攻击        |
| 日志     | 监控            |
| 路由     | 转发请求        |



------





# **Step 3 Load Balancer**





如果系统有很多服务器：

```
Server1
Server2
Server3
```

负载均衡负责：

```
request1 → server1
request2 → server2
request3 → server3
```

常见：



- Nginx
- HAProxy
- Kubernetes Service





------





# **Step 4 API 服务层**





进入后端服务：



例如：

```
FastAPI
Flask
Go
Node.js
```

这个服务负责：



- 解析用户输入
- 调用检索系统
- 调用 LLM
- 返回结果





------





# **Step 5 Query Processing（查询预处理）**





在真正检索前，会做一些处理：



例如：

```
文本清洗
拼写纠正
语言检测
query 改写
```

例如：



用户输入：

```
4090功耗
```

系统改写：

```
RTX4090 显卡功耗是多少
```



------





# **Step 6 Retrieval（知识检索）**





如果系统是 **RAG（Retrieval Augmented Generation）**：



就会检索知识库。



通常有两种方法：



------





## **BM25 检索**





关键词检索：

```
RTX4090
功耗
```

搜索文档。



------





## **向量检索**





流程：

```
query → embedding
```

然后在向量数据库里查：

```
Milvus
Faiss
Pinecone
Weaviate
```

找到：

```
TopK documents
```

例如：

```
doc1
doc2
doc3
```



------





# **Step 7 Reranker（重排序）**





检索出来的文档：

```
doc1
doc2
doc3
doc4
doc5
```

可能不完全准确。



使用 **Reranker（Cross Encoder）** 重新排序。



输出：

```
doc3
doc1
doc5
```

最相关的在前面。



------





# **Step 8 Prompt 构建**





把：



- 用户问题
- 检索到的知识





拼成 Prompt。



例如：

```
问题：
RTX4090 显卡功耗是多少？

参考资料：
1. RTX4090 TDP 450W
2. NVIDIA 官方说明功耗 450W

请回答用户问题。
```



------





# **Step 9 LLM 推理**





Prompt 发送给：

```
LLM 推理服务
```

例如：



- vLLM
- Triton
- HuggingFace TGI





推理流程：

```
Prompt
 ↓
Tokenizer
 ↓
Transformer
 ↓
Token generation
```

生成：

```
RTX4090 的官方 TDP 为 450W。
```



------





# **Step 10 Post-processing（后处理）**





生成后可能还会：



- 内容安全过滤
- 格式整理
- Markdown 渲染
- 生成引用来源





例如：

```
RTX4090 的官方 TDP 为 **450W**。

来源：
NVIDIA 官方文档
```



------





# **Step 11 返回结果**





最终 API 返回：

```
{
 "answer": "RTX4090 的官方 TDP 为 450W"
}
```

返回到：



- Web
- 手机
- Chat UI





------

# **四、推理服务器内部**





LLM 推理内部：

```
Request
 ↓
Tokenizer
 ↓
KV Cache
 ↓
Transformer Layers
 ↓
Sampling
 ↓
Next Token
```

循环直到：

```
EOS token
```



------





# **五、系统优化**





真实系统还会加入：

| **优化**  | **作用**        |
| --------- | --------------- |
| Cache     | 减少重复计算    |
| Batching  | 提高 GPU 利用率 |
| Streaming | 边生成边返回    |
| GPU 调度  | 提高吞吐        |



------





# **六、一句话总结（面试回答）**





如果面试官问：



**用户输入问题后系统怎么处理？**



可以回答：



> 在真实 AI 系统中，用户请求首先通过 API Gateway 和负载均衡进入后端服务，然后进行查询预处理。系统通常会通过向量检索或 BM25 从知识库中召回相关文档，并使用 Reranker 进行重排序。随后将用户问题和检索到的知识构建为 Prompt，发送给大语言模型推理服务生成答案。最后经过安全过滤和格式处理后，将结果返回给用户。
