# [解释模型并行的几种实现方式](https://github.com/lihe/MyGitBlog/issues/35)



我给你做一次**系统升级讲解**，分 7 层讲清楚：



1. 为什么需要模型并行
2. 数据并行 vs 模型并行
3. Pipeline 并行
4. Tensor 并行
5. MoE 专家并行
6. 3D 并行（真实大模型方案）
7. 通信代价本质





------





# **一、为什么需要模型并行？**





当模型参数太大：



- 单卡显存放不下
- 单卡算力不够





就必须：



> 把模型“拆开”到多卡上算



这就是模型并行。



------





# **二、数据并行 vs 模型并行**







## **数据并行（最简单）**





每张卡：



- 有完整模型
- 处理不同数据
- 梯度 AllReduce 同步





优点：



- 简单
- 通信只发生在反向





缺点：



- 模型必须能放进单卡





------





## **模型并行**





模型本身拆开。



优点：



- 能训练超大模型





缺点：



- 通信更复杂





------





# **三、Pipeline 并行（层间并行）**





核心思想：



> 按层拆模型



例如：



GPU1：Layer 1–12

GPU2：Layer 13–24

GPU3：Layer 25–36



------





## **数据像流水线流动**



```
Batch1 → GPU1 → GPU2 → GPU3
Batch2 → GPU1 → GPU2 → GPU3
```



------





## **优点**





- 通信少（只传激活值）
- 适合深模型





------





## **缺点**





- 存在 bubble（流水线空闲）
- 层数必须多





------





# **四、Tensor 并行（张量并行）**





核心思想：



> 把单层的矩阵拆开



例如：



Y = XW



W 是 8192 × 8192



拆成：



GPU1：算前一半列

GPU2：算后一半列



然后：



AllReduce 合并。



------





## **为什么适合 Transformer？**





Transformer 的：



- FFN
- Attention





矩阵特别大。



------





## **优点**





- 解决单层太大问题
- GPU 同时工作





------





## **缺点**





- 每层都要通信
- 通信频繁





------





# **五、专家并行（MoE）**





核心思想：



> 不同专家放不同 GPU



每个 token：



- 只激活部分专家





这样：



参数很大，但计算稀疏。



------





## **通信问题**





Token 需要：



- 被路由到不同 GPU





需要 All-to-All 通信。



------





# **六、真实世界：3D 并行**





现代大模型（如 GPT-3）使用：



> 数据并行 + Pipeline 并行 + Tensor 并行



称为：



> 3D Parallelism



例如：



- 8-way Tensor
- 8-way Pipeline
- 16-way Data





总 GPU：



8 × 8 × 16 = 1024



------





# **七、通信本质分析**





模型并行的核心瓶颈：



> GPU 之间通信



主要形式：



- AllReduce
- AllGather
- AllToAll





通信时间：



$T = \frac{DataSize}{Bandwidth} + Latency$



当模型变大：



通信成为主要瓶颈。



------





# **八、Pipeline vs Tensor 对比**



| **维度**   | **Pipeline** | **Tensor** |
| ---------- | ------------ | ---------- |
| 拆分方式   | 按层         | 按矩阵     |
| 通信频率   | 每层一次     | 每层多次   |
| 延迟       | 有 bubble    | 无 bubble  |
| 实现复杂度 | 中等         | 高         |



------





# **九、为什么 Transformer 特别适合张量并行？**





因为：



- 大量矩阵乘法
- attention 可拆
- FFN 可拆





而 CNN 不容易拆。



------





# **十、为什么 MoE 可以扩展到万亿参数？**





因为：



- 参数多
- 每次只算一部分





计算复杂度：



$O(active\_experts)$



而不是总专家数。



------





# **十一、现代主流框架**





- Megatron-LM → Tensor 并行
- DeepSpeed → ZeRO + Pipeline
- FSDP → 参数分片
- GShard → MoE





------





# **十二、推理阶段并行不同**





训练：



- 需要梯度同步





推理：



- 不需要梯度
- KV cache 可分布





所以推理并行更灵活。



------





# **十三、为什么大模型一定要混合并行？**





因为：



单一并行无法同时解决：



- 显存
- 计算
- 通信
- 扩展





必须：



> 多维并行联合。



------





# **十四、面试高质量回答**





如果问：



> 模型并行有哪些方式？



可以回答：



> 主要包括 Pipeline 并行（按层划分）、Tensor 并行（按矩阵划分）、以及 MoE 专家并行。此外在实际大模型训练中通常采用数据并行、Tensor 并行和 Pipeline 并行的三维混合并行策略，以平衡计算和通信开销。



------





# **十五、更深层理解**





模型并行本质是：



> 在计算图上切割节点



你可以把 Transformer 看成一个巨大的计算图：



- Pipeline → 切 layer
- Tensor → 切 matmul
- MoE → 切子网络





------





# **十六、真正高阶问题**





为什么：



- Tensor 并行需要 AllReduce？
- 为什么通信带宽限制模型规模？
- 为什么 NVLink 比 PCIe 重要？
- 为什么多机训练比单机慢很多？
