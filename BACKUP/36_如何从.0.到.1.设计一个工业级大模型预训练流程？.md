# [如何从 0 到 1 设计一个工业级大模型预训练流程？](https://github.com/lihe/MyGitBlog/issues/36)



# **一、数据阶段：真正决定模型上限的部分**





很多人以为训练最重要的是模型结构。



其实在大模型时代：



> 数据质量 ≥ 模型结构 ≥ 优化器细节



------





## **1️⃣ 数据清洗的核心原则**







### **(1) 去重（Deduplication）**





为什么重要？



- Common Crawl 里重复极多
- 重复数据会导致模型过拟合
- 有效 token 数下降





常用方法：



- MinHash
- SimHash
- n-gram fingerprint





------





### **(2) 质量过滤**





目标：



> 过滤低质量网页 / 垃圾文本



指标包括：



- perplexity filter
- 语言检测
- 重复率
- HTML 噪声比例
- 句子长度分布





GPT-3 论文中明确提到：



> 使用小模型对网页打分筛选。



------





### **(3) 数据分布平衡**





如果：



- 英文 90%
- 其他语言 10%





模型会严重偏向英文。



解决：



- 语言加权采样
- 任务重采样
- curriculum learning





------





# **二、数据存储与加载优化**





大规模训练时：



> IO 很可能成为瓶颈



------





## **为什么不用小文件？**





如果：



- 每个样本一个 txt
- 数千万文件





会导致：



- inode 爆炸
- 文件系统变慢





------





## **常用格式**





- TFRecord
- WebDataset
- MDS (Mosaic)
- Arrow
- HDF5





优点：



- 顺序读取
- 批量加载
- mmap 加速





------





# **三、Token 级批量设计**





大模型训练中：



我们关心的不是 batch size（样本数）



而是：



$\text{Global tokens per step}$



例如：



$4M tokens/step$



------





## **为什么用 token 数？**





因为：



- 不同样本长度不同
- 计算量与 token 数成正比





------





## **动态 batch 的本质**





目标：



$\text{固定每步 FLOPs}$



如果：



- 序列长 → batch 小
- 序列短 → batch 大





保持算力利用率。



------





# **四、优化器与学习率调度**





------





## **1️⃣ 为什么一定要 warmup？**





Transformer 初期梯度极不稳定。



直接用大 LR：



容易发散。



常用策略：



- 前 1% steps 线性升 LR
- 之后 cosine decay





------





## **2️⃣ 为什么 AdamW 是默认选择？**





因为：



- 自适应学习率
- 解耦 weight decay
- 稳定





LAMB：



- 用于超大 batch





Adafactor：



- 减少优化器内存





------





# **五、混合精度训练的本质**





FP16 问题：



- 数值范围小
- 容易 underflow





解决：



- Gradient Scaling





流程：



1. loss × scale
2. backward
3. 除回 scale





------



为什么必须用？



因为：



- 带宽减少 2 倍
- 显存减少 2 倍
- 算力翻倍





------





# **六、并行与通信优化**





------





## **1️⃣ 计算通信重叠**





关键思想：



> backward 时同时启动 AllReduce



这样：



通信时间隐藏在计算时间里。



------





## **2️⃣ 梯度累积**





如果显存不够：



分多次 forward/backward



再一起更新。



保持 global batch 不变。



------





# **七、监控与稳定性控制**





真正工业训练必须监控：



- loss
- grad norm
- lr
- 显存
- 通信时间
- GPU 利用率





否则：



一周训练可能白跑。



------





# **八、训练崩溃常见原因**





1. 学习率过大
2. 梯度爆炸
3. 数据异常
4. 权重初始化不稳定
5. 分布式通信死锁





------





# **九、一个真正高效的流程结构**





完整工业流程通常是：

```
数据清洗 → 去重 → 过滤 → 采样均衡
       ↓
Token 化 → 打包成 shards
       ↓
分布式加载 → 动态 batch
       ↓
混合精度 + ZeRO + 3D并行
       ↓
异步通信重叠
       ↓
监控与自动重启机制
```



------





# **十、效率的核心指标**







## **1️⃣ MFU (Model FLOPs Utilization)**





定义：



$\text{MFU} = \frac{实际 FLOPs}{理论峰值 FLOPs}$



好的系统：



> 40% – 60%



------





## **2️⃣ Tokens/sec**





真正衡量系统效率的指标。



------





# **十一、工程级优化清单**





真正做大模型预训练时你会做：



- Activation checkpoint
- ZeRO Stage 2/3
- Fused kernels
- FlashAttention
- Gradient clipping
- Async checkpoint save
- Prefetch data





------





# **十二、为什么预训练成本这么高？**





成本主要来自：



- GPU 时间
- 通信带宽
- 数据存储





而不是：



- 优化器选择





------





# **十三、面试级总结答案**





如果被问：



> 如何设计高效预训练流程？



你可以回答：



> 需要从数据质量、token级批量控制、混合精度、并行策略、通信重叠和系统监控六个方面系统设计。在工程上通过ZeRO分片、3D并行、FlashAttention和计算通信重叠提高MFU，并通过warmup和梯度裁剪保证稳定性。



------





# **十四、再往上一个层次的理解**





预训练本质是：



$\text{Compute Budget Optimization Problem}$



在固定算力预算下：



- 提高 token 利用率
- 提高 FLOPs 利用率
- 降低通信占比
- 提高数据质量





------
