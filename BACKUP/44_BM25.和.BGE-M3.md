# [BM25 和 BGE-M3](https://github.com/lihe/MyGitBlog/issues/44)

BM25 和 BGE-M3 是 **检索系统（Retrieval）里最常见的两类方法**，一个是 **稀疏检索（Sparse Retrieval）**，一个是 **稠密检索（Dense Retrieval）**。

它们经常被一起使用，比如 **RAG / 搜索系统 / 向量数据库 / 企业知识库**。



我会从 **原理 → 公式 → 特点 → 应用 → 为什么要混合使用** 帮你完整讲清楚。



------





# **一、BM25（稀疏检索）**





BM25 是 **传统搜索引擎的核心算法**。

Google 早期、ElasticSearch、Lucene 都在用。



它属于：



> **基于关键词匹配的检索算法**



------





# **1 BM25 的核心思想**





BM25 通过 **词频 + 逆文档频率** 来衡量相关性。



直觉：



一个词如果：



- 在当前文档里出现很多次
- 在整个语料库里很少见





那么这个词对检索非常重要。



------





# **2 BM25 公式**





BM25 的评分函数：



$score(q,d) = \sum_{t \in q} IDF(t) \cdot \frac{f(t,d) (k_1 + 1)} {f(t,d) + k_1(1-b+b\frac{|d|}{avgdl})}$



解释一下：

| **符号** | **含义**           |
| -------- | ------------------ |
| q        | 查询               |
| d        | 文档               |
| t        | 词                 |
| f(t,d)   | 词在文档中出现次数 |
| IDF      | 逆文档频率         |
| k1,b     | 调节参数           |



------





# **3 IDF（逆文档频率）**





$IDF(t) = \log \frac{N - n_t + 0.5}{n_t + 0.5}$



含义：

| **变量** | **含义**         |
| -------- | ---------------- |
| N        | 文档总数         |
| nt       | 包含该词的文档数 |



------



举例：



假设：

```
N = 10000
nt = 10
```

说明这个词很稀有。



IDF 很高。



------





# **4 BM25 的三个核心因素**







### **① 词频（TF）**





词出现越多 → 越重要



但 BM25 不会线性增长。



------





### **② IDF**





词越稀有 → 权重越高



------





### **③ 文档长度归一化**





长文档天然词多。



BM25 会进行惩罚。



------





# **5 BM25 的优点**







### **优点**





1️⃣ 非常快

2️⃣ 可解释

3️⃣ 不需要训练

4️⃣ 对关键词搜索非常好



------





# **6 BM25 的缺点**





BM25 **不理解语义**。



例如：



查询：

```
car
```

文档：

```
automobile
```

BM25 不知道是同义词。



------





# **二、BGE-M3（稠密检索）**





BGE-M3 是 **最新的 embedding 检索模型**。



由：



> **BAAI（智源研究院）** 提出。



模型名字：



**BAAI General Embedding – M3**



------





# **1 BGE-M3 的目标**





BGE-M3 想解决三个问题：



1️⃣ 多语言

2️⃣ 多粒度

3️⃣ 多检索方式



因此叫：



**M3 = Multi-lingual, Multi-granularity, Multi-function**



------





# **2 Dense Retrieval（稠密检索）**





BGE-M3 的思路：



把文本变成 **向量**。



例如：

```
query → embedding vector
doc → embedding vector
```

然后计算：



$similarity = q \cdot d$



或者：



cosine(q,d)



------





# **3 Dense Retrieval 的优势**





语义匹配。



例如：



查询：

```
car
```

文档：

```
automobile
```

embedding 很接近。



------





# **4 BGE-M3 的三种检索方式**





BGE-M3 特别强的地方在于：



**一个模型支持三种检索**



------





## **① Dense Retrieval**





语义检索。



向量相似度。



------





## **② Sparse Retrieval**





类似 BM25。



模型直接预测关键词权重。



------





## **③ Multi-vector Retrieval**





每个文档生成多个向量。



更细粒度。



------





# **5 BGE-M3 的结构**





BGE-M3 基于：

```
Transformer Encoder
```

输入：

```
text → token → encoder
```

输出：

```
embedding vector
```



------





# **6 BGE-M3 的特点**







### **多语言**





支持：

```
100+ languages
```



------





### **长文本**





支持：

```
8192 tokens
```



------





### **高性能**





在 MTEB benchmark 上非常强。



------





# **三、BM25 vs BGE-M3**



| **维度**     | **BM25** | **BGE-M3** |
| ------------ | -------- | ---------- |
| 类型         | Sparse   | Dense      |
| 语义理解     | ❌        | ✅          |
| 速度         | 非常快   | 较慢       |
| 是否需要训练 | 不需要   | 需要       |
| 是否需要 GPU | 不需要   | 需要       |
| 同义词识别   | ❌        | ✅          |



------





# **四、为什么要 Hybrid Search**





现在最主流的做法是：



> **BM25 + Dense Retrieval**



原因：



两者互补。



------





### **BM25 擅长**





关键词匹配。



例如：

```
RTX4090 显卡功耗
```



------





### **Dense Retrieval 擅长**





语义理解。



例如：

```
如何降低 GPU 功耗
```



------





# **五、Hybrid Search（混合检索）**





混合方法：



$Score = \alpha \cdot BM25 + (1-\alpha) \cdot DenseScore$



例如：

```
Score = 0.4 * BM25 + 0.6 * embedding
```



------





# **六、RAG 中的典型架构**





现在 RAG 系统通常：

```
Query
   ↓
Hybrid Retrieval
(BM25 + BGE)
   ↓
TopK documents
   ↓
LLM
```



------





# **七、企业级检索架构**





真实系统：

```
query
  ↓
BM25召回
  ↓
Embedding召回
  ↓
Merge
  ↓
Cross-Encoder rerank
  ↓
Top documents
```



------





# **八、为什么还需要 Reranker**





Dense Retrieval 有个问题：



只计算向量相似度。



不够精确。



因此会用：

```
Cross Encoder
```

重新排序。



例如：

```
bge-reranker
```



------





# **九、总结一句话**





BM25：



> 基于关键词的传统检索算法。



BGE-M3：



> 基于 Transformer embedding 的语义检索模型。



现代检索系统：



> **BM25 + Dense Retrieval + Reranker**
