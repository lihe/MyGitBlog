# [在推荐或 RAG 中如何完成亿级向量的快速检索？——IVFPQ](https://github.com/lihe/MyGitBlog/issues/26)





# **一句话速答（面试先说）**





> IVFPQ 是一种结合倒排索引（Inverted File）和乘积量化（Product Quantization）的近似最近邻搜索算法，通过“先分桶缩小搜索范围，再对向量压缩编码”来实现大规模向量的高效检索。



------





# **一、为什么需要 IVFPQ？**





假设：



- 有 1 亿条向量
- 每条 768 维
- 需要实时搜索最近邻





如果用暴力搜索：



O(ND)



计算量极大。



IVFPQ 目标是：



> 在保证可接受精度下，大幅减少计算量和存储开销。



------





# **二、IVFPQ 的两个核心组件**





IVFPQ = IVF + PQ



------





# **第一部分：IVF（Inverted File）**







## **核心思想**





> 先用聚类把数据分成很多“桶”（cluster）



步骤：



1. 对所有向量做 k-means 聚类
2. 得到 K 个中心（centroids）
3. 每个向量分配到最近的中心





形成结构：

```
cluster 1 → 向量列表
cluster 2 → 向量列表
...
```

这就是“倒排索引”。



------





## **查询时**





给定 query：



1. 找最近的 n 个 cluster
2. 只在这些 cluster 里搜索





👉 搜索范围大幅缩小



------





# **第二部分：PQ（Product Quantization）**





IVF 解决了“搜哪里”，

PQ 解决了“怎么快算距离 + 怎么省内存”。



------





## **PQ 核心思想**





把一个高维向量：



$x \in \mathbb{R}^D$



拆成：



m 个子向量



例如：



- D=768
- m=96
- 每个子向量 8 维





对每个子空间单独做 k-means（例如 256 个中心）



于是：



每个子向量只需要：

```
1 byte（0~255）
```

整个向量只需：

```
m bytes
```

比如：



96 bytes 而不是 768 × 4 bytes



👉 存储压缩 30 倍以上



------





# **三、检索流程**





查询步骤：



1️⃣ 找最近的几个 cluster（IVF）

2️⃣ 对每个候选向量：



- 用 PQ 近似距离计算

- 查表计算

  3️⃣ 选 TopK





------





# **四、为什么 PQ 距离计算很快？**





因为：



- 子向量距离可以预先算好
- 用查表方式加和
- 不需要还原原始向量





这叫：



> Asymmetric Distance Computation (ADC)



------





# **五、IVFPQ 整体流程总结**



```
构建阶段：
    聚类 → 分桶
    每个向量做 PQ 编码

查询阶段：
    找最近的 cluster
    用 PQ 近似计算距离
    排序返回
```



------





# **六、为什么 IVFPQ 能支持亿级数据？**





因为：



- 不需要全量扫描
- 向量被压缩成几十字节
- 距离计算用查表





时间复杂度大幅降低。



------





# **七、优缺点**







## **优点**





- 存储压缩率高
- 查询速度快
- 支持大规模





------





## **缺点**





- 精度损失
- 参数调节复杂
- 需要预训练聚类





------





# **八、IVFPQ vs HNSW**



| **方法** | **类型**    | **特点** |
| -------- | ----------- | -------- |
| IVFPQ    | 量化 + 分桶 | 内存小   |
| HNSW     | 图结构      | 精度高   |

通常：



- 内存敏感 → IVFPQ
- 高精度需求 → HNSW





------





# **九、在 RAG 里的作用**





在 RAG 中：



- 向量库可能百万/千万条文档
- 需要快速召回
- 常用 FAISS IVFPQ 或 Milvus 实现





------





# **十、面试标准总结（建议背）**





> IVFPQ 是一种结合倒排索引和乘积量化的近似最近邻搜索算法，通过先将向量分桶缩小搜索范围，再对向量进行压缩编码，实现大规模向量的高效存储和快速检索。



------





# **一句更高级的总结**





> IVFPQ 本质是“先粗筛，再压缩算”。
